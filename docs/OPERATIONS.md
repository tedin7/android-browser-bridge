## Input schemas

Machine-readable per-operation input schemas live in `operations.json` and the generated extension catalog.
`operation_registry.validate_arguments()` validates the supported JSON Schema subset without dependencies, including every batch step before dispatch.
The generated JavaScript validator checks inputs before Firefox dispatch, including the entire batch with inherited tab/workflow arguments. Native companion contracts remain separate.
Output schemas describe successful raw Firefox results before compaction, not MCP envelopes or errors. `validate_result()` / `validateResult()` are explicit conformance helpers, not post-mutation rejection. Extensible diagnostic objects and site-defined WebMCP result payloads intentionally permit additional fields.
